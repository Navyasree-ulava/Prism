## Interpretation (for the report)

1. **The router beats random selection by 7.8 pp** — meaningful given the
   baseline is already high (acceptable sets cover most of a 3-model registry,
   so random picking does well by construction). The gain comes from the
   capability filter + weighted scoring consistently preferring the model
   labeled acceptable for that task type.

2. **Cost-aware routing works**: sending every query to the flagship model
   would cost 2.4× more ($0.0377 vs $0.0156 for the same 60 queries) while
   losing almost no accuracy — the cheap-tier models absorb the simple
   qa/summarization traffic that dominates the dataset.

3. **Routing overhead is negligible** (~0.06 ms/query), i.e. the explainable
   scoring engine adds no perceptible latency compared to provider call times
   (100s of ms).

4. **Fallback recovers most primary failures** — with the top-ranked provider
   mocked to fail, 71.7% of requests completed via the next-ranked candidate
   (one hop, as specced). The remainder either had a single eligible candidate
   or failed both.

5. **Analyzer comparison — the honest result**: on this dataset the tuned
   keyword/regex heuristic (96.7%) **outperforms** the small LLM classifier
   `allam-2-7b` (76.7%). The heuristic encodes dataset-visible patterns
   (code fences, "TL;DR", question shape) directly, while a 7B model
   mislabels edge cases (e.g. creative prompts with task-like verbs) and
   occasionally confuses `general` vs `qa`. This supports the project's
   default `ANALYZER_MODE=heuristic`: the LLM mode remains available for
   prompts that resist keyword rules, but the heuristic is both free and more
   accurate here.

## Measurement integrity

- The LLM column uses `strict=True`: every one of the 60 classifications was
  a real LLM response (`llm_classified=60`, `llm_failed=0`); no
  heuristic-fallback result is counted as an LLM classification.
- Calls are paced (1.5 s interval, 429 backoff) to respect Groq free-tier
  rate limits.
- An earlier same-day draft run (`report_20260922_042901`) was discarded: its
  LLM column was contaminated by silent fallbacks after rate-limit errors and
  is not part of the results.
